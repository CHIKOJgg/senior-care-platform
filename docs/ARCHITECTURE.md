# Архитектура системы

## 1. Архитектурный стиль
Проект реализован по паттерну **MVC (Model-View-Controller)** с RESTful API на языке **PHP 8.2+**.

* **Model:** инкапсулирует сущности предметной области, правила валидации и запросы к СУБД через PDO.
* **View:** интерфейс с поддержкой двух режимов отображения (Стандартный / Адаптированный для пожилых людей), использующий HTML5, CSS3, JavaScript и Web Speech API.
* **Controller:** принимает HTTP-запросы, взаимодействует с сервисами бизнес-логики и возвращает JSON или HTML-представления.
* **Services:** сервисный слой, вынесенный из контроллеров (GeoMatchingService, SecurityService, AntiFraudService).

## 2. Спецификация REST API
| Метод | Маршрут | Описание | Доступ |
|---|---|---|---|
| POST | /api/auth/register | Регистрация подопечного / волонтёра | Public |
| POST | /api/auth/login | Вход в систему | Public |
| GET | /api/requests | Список открытых заявок с гео-фильтрацией | Волонтёр, Координатор |
| POST | /api/requests | Создание новой заявки | Подопечный |
| GET | /api/requests/{id} | Детали заявки со статусом и проверочным кодом | Подопечный, Волонтёр |
| POST | /api/requests/{id}/accept | Взятие заявки в работу волонтёром | Волонтёр |
| POST | /api/requests/{id}/complete | Завершение заявки | Волонтёр |
| POST | /api/antifraud/check | Проверка подозрительного номера/фразы | Все |
| GET | /api/education/materials | Список обучающих памяток и аудиоуроков | Все |

## 3. Алгоритм гео-подбора (Geo-matching)
Для сопоставления открытой заявки с волонтёрами применяется формула гаверсинусов:
дистанция рассчитывается по географическим координатам (широта/долгота).
Итоговый скоринг кандидата:
Score = w_dist * (1 - dist / max_radius) + w_rating * (rating / 5.0) + w_skills * skill_match
