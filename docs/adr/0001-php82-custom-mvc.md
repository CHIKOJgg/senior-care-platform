# ADR-0001. PHP 8.2 и собственное MVC-ядро без фреймворка

- **Статус:** Принято
- **Дата:** 2026-11-22
- **Категория:** Backend
- **Связанные ADR:** [ADR-0002](0002-vanilla-js-frontend-wcag.md), [ADR-0004](0004-pdo-idempotent-migrations.md), [ADR-0006](0006-zero-composer-custom-libraries.md)

## Контекст

Платформа обслуживает пожилых людей, волонтёров, координаторов ТЦСОН и администраторов. Код должен быть компактным, проверяемым и запускаться без сборки, Composer и тяжёлого runtime. При этом есть чувствительные операции: расшифровка медицинских заметок, проверка кодового слова, отзыв токенов, SOS и обезличивание данных.

## Решение

Используется PHP 8.2+ с `declare(strict_types=1)` и собственное MVC-ядро:

```text
public/index.php     HTML-интерфейс и серверный выбор роли
public/api.php       front controller REST API
public/verify.php    публичная проверка QR-бейджа
app/Core/            Router, Database, Model, Logger, RateLimiter, MetricsService
app/Controllers/     Auth, HelpRequest, Coordinator, Volunteer, SOS, Privacy
app/Models/          PDO-модели домена
app/Services/        Auth, Crypto, Privacy, GeoMatching, Badge, Watchdog
router.php           точка входа для встроенного сервера
```

Ключевые элементы:

- Router поддерживает `GET`, `POST`, `PUT`, `DELETE`, параметры `{id}`, JSON-ответы и security-заголовки.
- Model инкапсулирует PDO CRUD и проверяет имена колонок.
- Сервисный слой содержит криптографию, геоматчинг, приватность, бейджи, watchdog и интеграционные адаптеры.
- HTML-шаблон находится в `public/index.php`; отдельного шаблонизатора нет.

## Обоснование

1. Полный контроль над чувствительной логикой и её аудит.
2. Нет Composer, vendor-каталога и конфликтов зависимостей.
3. Запуск одной командой или одним Docker Compose-стеком.
4. Строгая типизация уменьшает ошибки в координатах, TTL и лимитах.
5. Небольшой домен не требует ORM, DI-контейнера и шаблонизатора.

## Последствия

### Положительные

- Компактная и обозримая кодовая база.
- Быстрый старт для разработчика, знающего PHP и PDO.
- Простая контейнеризация и отсутствие шага сборки фронтенда.

### Отрицательные / риски

- Собственный роутер, автозагрузчик и security-заголовки нужно поддерживать самостоятельно.
- Нет готовых middleware, валидаторов и ORM.
- HTML и JS-логика сосредоточены в крупных файлах, что требует дисциплины.

## Альтернативы

| Альтернатива | Почему не выбрана |
|---|---|
| Laravel | Composer, Eloquent, Blade и инфраструктурная избыточность для 13 таблиц |
| Symfony | Большой bootstrap и высокая стоимость сопровождения |
| Slim | Всё равно требует Composer и отдельных библиотек для ORM/auth |
| Скрипты без MVC | Быстро на старте, но плохо масштабируется и усложняет RBAC |
