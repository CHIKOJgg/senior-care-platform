# ADR-0006. Нулевые Composer-зависимости и собственные библиотеки

- **Статус:** Принято
- **Дата:** 2026-11-08
- **Категория:** Библиотеки
- **Связанные ADR:** [ADR-0001](0001-php82-custom-mvc.md), [ADR-0005](0005-hmac-auth-and-rate-limiting.md), [ADR-0007](0007-aes256gcm-and-data-masking.md)

## Контекст

Проект должен:

- запускаться на любом окружении с PHP 8.2 без `composer install`;
- не зависеть от внешних пакетов и их уязвимостей;
- быть полностью аудируемым (криптография, QR, токены);
- работать в offline/изолированной среде (демо, стенд, CI);
- не требовать интернета при деплое.

При этом нужны нетривиальные функции: QR-коды, Reed-Solomon, HMAC-бейджи, AES-256-GCM, маршрутизация, логирование, метрики, rate limiting.

## Решение

**Composer не используется.** В репозитории нет `composer.json`, `vendor/` и composer-автозагрузчика. Вместо этого реализованы собственные компоненты:

| Компонент | Файл | Что делает |
|---|---|---|
| Автозагрузчик | `public/api.php` | `spl_autoload_register` для префикса `App\` |
| Роутер | `app/Core/Router.php` | regex-маршруты, JSON, security-заголовки, метрики |
| Модель | `app/Core/Model.php` | PDO CRUD с валидацией идентификаторов |
| Логгер | `app/Core/Logger.php` | файловый лог с уровнями `INFO/WARNING/ERROR/SECURITY` |
| Rate limiter | `app/Core/RateLimiter.php` | файловые окна с `LOCK_EX` |
| Метрики | `app/Core/MetricsService.php` | Prometheus-формат, JSON-счётчики, DB-gauges |
| Крипто | `app/Services/CryptoService.php` | AES-256-GCM через OpenSSL |
| HMAC-бейджи | `app/Services/BadgeService.php` | подпись, TTL, верификация, SVG-бейдж |
| QR-энкодер | `app/Services/BadgeService.php` | ISO/IEC 18004: byte mode, EC L, GF(256), Reed-Solomon, маска 0, SVG run-length |
| Геоматчинг | `app/Services/GeoMatchingService.php` | Haversine, geofence 150 м, скоринг |
| Маскирование | `app/Services/DataMaskingService.php` | телефоны и адреса по Закону № 99-З |
| Приватность | `app/Services/PrivacyService.php` | согласия, обезличивание |
| Watchdog | `app/Services/TaskWatchdogService.php` | тайм-ауты категорий |
| Адаптеры | `app/Services/Identity/*`, `Emergency/*` | МСИ, ЕСИА, МЧС 112 |

Используются только встроенные расширения PHP: `pdo`, `pdo_sqlite`, `pdo_mysql`, `openssl`, `mbstring`, `json`, `curl` (для healthcheck/CI).

## Обоснование

1. **Развёртывание в одно действие.** Нет `composer install`, `vendor/`, lock-файлов и сетевых запросов при сборке. Это важно для закрытых/учебных стендов.
2. **Безопасность цепочки поставок.** Нет сторонних пакетов — нет риска typosquatting, compromise dependency, уязвимых транзитивных зависимостей.
3. **Аудит.** Криптография и QR-код написаны явно и покрыты тестами; можно объяснить каждую строку.
4. **Контроль поведения.** Собственный роутер и логгер не меняют поведение между версиями.
5. **Offline-first.** QR-генерация и криптография работают без интернета и внешних API.
6. **Соответствие PROJECT.md.** Документ прямо фиксирует «without external Composer dependencies».

## Последствия

### Положительные

- Нет `vendor/` и конфликтов версий.
- Сборка Docker проще и быстрее.
- Все зависимости — расширения PHP, которые ставятся в Dockerfile.
- Легко пройти аудит и объяснить происхождение кода.
- Нет риска, что пакет перестанет поддерживаться.

### Отрицательные / риски

- **Высокая стоимость сопровождения.** Свой роутер, логгер, метрики, QR и крипто-обёртки нужно развивать и тестировать самостоятельно.
- **Риск ошибок в криптографии и QR.** Реализация Reed-Solomon/GF(256) и формата QR — сложная область; ошибки могут быть неочевидны. Смягчение — тесты (`tests/test_badge.php`, adversarial-тесты).
- **Нет обновлений безопасности от upstream.** Если в алгоритме/подходе найдётся проблема, исправлять нужно вручную.
- **Ограниченная функциональность.** Нет готовых валидаторов, шаблонизаторов, очередей, i18n, PSR-7/PSR-15.
- **Совместимость с инструментами.** PHPStan/Psalm/IDE не видят composer-автозагрузку; статический анализ требует настройки.
- **Собственный формат токена/бейджа** несовместим со сторонними библиотеками (см. ADR-0005).

### Нейтральные

- Часть «библиотек» фактически является сервисами предметной области, а не переиспользуемыми пакетами.
- QR-код поддерживает версии 1–20 и уровень коррекции L; этого достаточно для URL бейджа, но не для произвольных больших payload.

## Рассмотренные альтернативы

| Альтернатива | Почему отклонена |
|---|---|
| **endroid/qr-code** | Composer-зависимость и GD/Imagick; проект рисует SVG без расширений. |
| **chillerlan/php-qrcode** | Мощная, но тяжёлая зависимость; нарушает принцип zero-deps. |
| **firebase/php-jwt** | Не нужен, токен собственный (ADR-0005); добавляет зависимость. |
| **monolog/monolog** | Избыточен для файлового лога с 4 уровнями. |
| **symfony/routing, symfony/http-foundation** | Тянут компоненты и Composer; проект сознательно минималистичен. |
| **Guzzle** | Нет реальных HTTP-интеграций (адаптеры эмулируют ответы); `curl` достаточно. |
| **PHPUnit** | Заменён собственным harness (ADR-0012). |
