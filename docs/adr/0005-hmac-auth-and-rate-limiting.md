# ADR-0005. Stateless HMAC-токены, HttpOnly-cookie, token_version и rate limiting

- **Статус:** Принято
- **Дата:** 2026-11-22
- **Категория:** Безопасность
- **Связанные ADR:** [ADR-0006](0006-zero-composer-custom-libraries.md), [ADR-0011](0011-docker-caddy-nginx-phpfpm.md), [ADR-0013](0013-backups-secrets-healthchecks.md)

## Контекст

Нужно разделить доступ для четырёх ролей, обеспечить удобный вход пожилому человеку, поддержать API-клиенты и тесты, а также мгновенно отзывать сессии без Redis и общего session store.

## Решение

### Токены

`AuthService` формирует stateless HMAC-SHA256-токен:

```text
base64(json(payload)) + "." + hex(hmac_sha256(base64(payload), APP_SECRET))
```

Payload содержит `user_id`, `role_id`, `role_code`, `phone`, `name`, `tv`, `iat`, `exp`.

- TTL сотрудника: 7 дней.
- TTL устройства подопечного: 365 дней.
- Токен принимается из `Authorization: Bearer`, `X-Auth-Token` или HttpOnly-cookie `auth_token`.
- Подпись проверяется через `hash_equals`.
- В production отсутствие `APP_SECRET` — ошибка конфигурации.

### Отзыв сессий

В `users.token_version` хранится версия токена. Смена пароля, сброс пароля и выход на всех устройствах увеличивают `token_version`; старые токены отклоняются при следующем запросе.

### RBAC

`AuthService::requireAuth($allowedRoles)` возвращает `401` без аутентификации и `403` при недостаточной роли. Администратор получает доступ туда, где разрешён координатор.

### Rate limiting

`RateLimiter` хранит окна в `storage/cache/rate_limits/*.json` с `LOCK_EX`:

- логин — 10 попыток / 300 секунд на IP;
- смена пароля — 5 попыток / 300 секунд на пользователя;
- выдача кодов восстановления — 10 запросов / 300 секунд;
- успешный логин очищает счётчик.

### Пароли

Используются `password_hash()` и `password_verify()` с `PASSWORD_DEFAULT`.

### Локальный режим

В `APP_ENV=local` без токена доступен демонстрационный администратор; `X-Demo-User` позволяет выбрать пользователя. В production эта ветка недоступна. На `/` без токена доступен гостевой режим подопечного, а для создания заявки требуется вход через `/login`.

## Обоснование

1. Нет серверного хранилища сессий и Redis.
2. Долгий вход подопечного решает проблему ввода пароля.
3. `token_version` даёт мгновенный отзыв без blacklist.
4. Подпись и проверка пользователя в БД сочетают stateless-подход и контроль актуальности.
5. Файловый rate limiter достаточен для одного узла.

## Последствия

### Положительные

- Горизонтальное масштабирование без sticky sessions.
- Мгновенный отзыв всех токенов.
- Работа с cookie и API-клиентами.
- Пароли и токены не пишутся в логи.

### Отрицательные / риски

- Это не RFC 7519 JWT: нет `alg`, `kid` и стандартных claim-имён.
- Смена `APP_SECRET` инвалидирует все токены.
- Нет refresh-токенов.
- Файловый rate limiter не распределён между узлами.
- Нет отдельного CSRF-токена; используется `SameSite=Lax`.

## Альтернативы

| Альтернатива | Почему не выбрана |
|---|---|
| PHP-сессии | Нужен общий session store при нескольких PHP-FPM |
| Стандартный JWT | Лишняя зависимость и риск неверной настройки |
| OAuth2/OIDC | Избыточен без внешних клиентов |
| Redis-сессии | Дополнительный сервис и эксплуатация |
