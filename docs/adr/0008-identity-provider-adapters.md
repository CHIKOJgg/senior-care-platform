# ADR-0008. Адаптеры верификации МСИ РБ и ЕСИА

- **Статус:** Принято
- **Дата:** 2026-11-22
- **Категория:** Интеграции
- **Связанные ADR:** [ADR-0006](0006-zero-composer-custom-libraries.md), [ADR-0007](0007-aes256gcm-and-data-masking.md)

## Контекст

Допуск волонтёра к пожилому человеку требует проверки личности. Платформа ориентирована на Беларусь, но допускает российских волонтёров через ЕСИА. Реальные государственные API требуют договоров, сертификатов и недоступны в демонстрационной среде. Интеграция должна быть заменяемой и не хранить исходные идентификаторы в открытом виде.

## Решение

Используется интерфейс провайдера и фабрика адаптеров:

```text
app/Services/Identity/
├── IdentityProviderInterface.php
├── MsiIdentityAdapter.php
├── GosuslugiIdentityAdapter.php
└── IdentityProviderFactory.php
```

### МСИ РБ

- 14-значный личный номер гражданина;
- проверка формата и даты рождения;
- определение региона и типа документа;
- маскирование номера;
- KYC-токен и хеш идентификатора вместо открытого номера.

### ЕСИА

- СНИЛС в формате `XXX-XXX-XXX YY` или 11 цифр;
- контрольная сумма по модулю 101;
- маскирование;
- KYC-токен.

### Фабрика

`IdentityProviderFactory::get('msi'|'gosuslugi')` возвращает нужный адаптер. Неизвестный провайдер вызывает `InvalidArgumentException`.

Адаптеры детерминированно эмулируют ответы и не выполняют сетевых вызовов. Это позволяет тестировать верификацию без доступа к государственным API.

## Обоснование

1. Бизнес-логика зависит от интерфейса, а не от конкретного API.
2. Подключение реального шлюза требует только нового адаптера.
3. Детерминированные ответы позволяют покрыть сценарии в CI.
4. В БД попадают маска, хеш и KYC-токен, а не исходный документ.
5. Поддерживаются две юрисдикции.

## Последствия

### Положительные

- Заменяемость провайдера.
- Один UI для МСИ и ЕСИА.
- Нет сетевой зависимости в тестах.
- Минимизация персональных данных.

### Отрицательные / риски

- Адаптеры являются эмуляторами, а не реальными интеграциями.
- Форматная валидация не заменяет проверку в государственном реестре.
- Нет retry, circuit breaker и аудита request/response ID.
- Срок жизни KYC-токена не формализован.

## Альтернативы

| Альтернатива | Почему не выбрана |
|---|---|
| Вызовы API из контроллера | Жёсткая связанность и сложность тестирования |
| Один адаптер с `if` | Нарушает расширяемость |
| SDK провайдера | Нет доступных SDK и Composer-политика |
| Ручная проверка без адаптеров | Нет автоматической валидации формата |
