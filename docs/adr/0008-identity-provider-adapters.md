# ADR-0008. Адаптеры верификации МСИ РБ и ЕСИА (Госуслуги)

- **Статус:** Принято
- **Дата:** 2026-11-08
- **Категория:** Интеграция
- **Связанные ADR:** [ADR-0006](0006-zero-composer-custom-libraries.md), [ADR-0007](0007-aes256gcm-and-data-masking.md)

## Контекст

Доступ волонтёра к пожилому человеку — это высокий риск. Платформа требует проверки личности и отсутствия судимости. При этом:

- волонтёры могут быть гражданами Республики Беларусь (личный номер паспорта) или РФ (СНИЛС/ЕСИА);
- реальные государственные API (МСИ, ЕСИА) требуют договоров, сертификатов, IP-белых списков и не доступны в учебном/демо-стенде;
- интеграция должна быть заменяемой, чтобы подключить реальный провайдер без переписывания бизнес-логики;
- ПДн нельзя хранить в открытом виде (см. ADR-0007).

## Решение

Введён **интерфейс провайдера идентификации** и **фабрика адаптеров**:

```text
app/Services/Identity/
├── IdentityProviderInterface.php   # getProviderName, authenticate, verifyIdentity, fetchProfile
├── MsiIdentityAdapter.php          # МСИ Республики Беларусь
├── GosuslugiIdentityAdapter.php    # ЕСИА / Госуслуги РФ
└── IdentityProviderFactory.php     # msi | gosuslugi (+ алиасы)
```

### МСИ РБ (`MsiIdentityAdapter`)

- формат личного номера: `/^[1-6]\d{6}[A-Z]\d{3}[A-Z]{2}\d$/` (14 символов);
- парсинг пола/века по первой цифре;
- проверка даты рождения через `checkdate()`;
- карта регионов (A — Минск, B — Брест, C — Витебск, E — Гомель, K — Гродно, M — Могилёв, H — Минская обл.);
- типы документов `PB`, `BA`, `BI`;
- маскирование: `3010190A***PB5`;
- сохраняется SHA-256 хеш идентификатора и KYC-токен `kyc_msi_...`;
- есть детерминированные тестовые кейсы (`VERIFIED`, `SECURITY_ALERT`, `CRIMINAL_RECORD`).

### ЕСИА / Госуслуги (`GosuslugiIdentityAdapter`)

- формат СНИЛС: `XXX-XXX-XXX YY` или 11 цифр;
- контрольная сумма по модулю 101 с историческим исключением `<= 001001998`;
- маскирование: `***-***-445 95`;
- KYC-токен `kyc_esia_...`;
- тестовые кейсы `CONFIRMED`, `UNCONFIRMED`, `BLOCKED`.

### Фабрика

`IdentityProviderFactory::get('msi'|'gosuslugi')` возвращает нужный адаптер; неизвестный провайдер — `InvalidArgumentException`. `getAvailableProviders()` отдаёт метаданные для UI.

## Обоснование

1. **Заменяемость.** Бизнес-логика зависит от интерфейса, а не от конкретного госAPI. Подключение реального шлюза — новый адаптер, а не правки контроллеров.
2. **Тестируемость без сети.** Детерминированные ответы позволяют прогонять сценарии верификации, отказа и блокировки в CI.
3. **Минимизация ПДн.** В БД попадают маска, хеш и KYC-токен, а не исходный номер документа.
4. **Поддержка двух юрисдикций.** Платформа ориентирована на РБ, но допускает российских волонтёров через ЕСИА.
5. **Единый контракт.** `verifyIdentity()` возвращает `success/verified/claims/kyc_token`, что упрощает координатору модерацию.
6. **Нет Composer-зависимостей.** Валидация и парсинг реализованы на встроенных функциях PHP (ADR-0006).

## Последствия

### Положительные

- Легко добавить нового провайдера (например, украинский/казахстанский).
- Один и тот же UI для двух провайдеров.
- Верификация не блокирует разработку при отсутствии доступа к госAPI.
- Чувствительные идентификаторы не хранятся в открытом виде.

### Отрицательные / риски

- **Это эмуляторы, а не реальные интеграции.** Нет HTTP-вызовов, OAuth-редиректов, подписи запросов, mTLS и обработки ошибок сети. Для production нужен реальный адаптер и договор с оператором.
- **Детерминированные тестовые личности.** Список `knownIdentities` — демо-данные; в production их быть не должно.
- **Ложное чувство безопасности.** Форматная валидация не равна проверке в госреестре; координатор всё равно должен видеть документы.
- **Нет кэширования/повторных попыток.** При реальном API понадобятся retry, circuit breaker, таймауты.
- **Нет аудита вызовов провайдера.** Логируются только факты, но не request/response ID.
- **Хранение KYC-токена.** Срок жизни и отзыв токена не формализованы.

### Нейтральные

- `fetchProfile()` возвращает демо-профиль по префиксу токена.
- Адаптеры не делают сетевых вызовов, поэтому работают offline.

## Рассмотренные альтернативы

| Альтернатива | Почему отклонена |
|---|---|
| **Прямые вызовы МСИ/ЕСИА из контроллера** | Жёсткая связанность, невозможно тестировать без сети, дублирование. |
| **Один адаптер с `if`-ветками** | Нарушает Open/Closed, усложняет добавление провайдеров. |
| **SDK провайдера** | Нет публичных SDK/Composer-пакетов; нарушает zero-deps. |
| **Ручная проверка координатором без адаптеров** | Не даёт автоматической валидации формата и KYC-токена, повышает нагрузку. |
| **Хранить номер документа открыто** | Нарушает минимизацию ПДн и Law 99-Z. |
