# ADR-0004. PDO и идемпотентные миграции на чистом PHP

- **Статус:** Принято
- **Дата:** 2026-11-22
- **Категория:** Данные
- **Связанные ADR:** [ADR-0003](0003-database-sqlite-mysql.md), [ADR-0006](0006-zero-composer-custom-libraries.md)

## Контекст

Схема развивается вместе с функциями платформы: добавляются регионы, SOS, согласия, коды восстановления, бейджи и телеметрия выполнения. Миграции должны быть безопасны при рестарте контейнеров и повторных запусках, поддерживать SQLite и MySQL и не требовать Phinx/Doctrine.

## Решение

`database/migrate.php` — идемпотентный скрипт на чистом PHP:

1. Определяет драйвер PDO.
2. Проверяет наличие таблиц через `sqlite_master` или `INFORMATION_SCHEMA`.
3. Получает список колонок через `PRAGMA table_info` или `INFORMATION_SCHEMA.COLUMNS`.
4. Добавляет недостающие nullable-колонки.
5. Применяет `CREATE TABLE IF NOT EXISTS` и индексы.
6. Выполняет backfill `region_code` по координатам.
7. Синхронизирует `verification_status` с `is_verified`.
8. Шифрует legacy-значения `mobility_notes` с префиксом `enc:v1:`.

Все запросы к данным выполняются через PDO prepared statements. `Model` проверяет имена колонок и операторы по белому списку.

## Обоснование

1. Повторный запуск не ломает существующую схему.
2. Один механизм для SQLite, MySQL, CI и контейнеров.
3. Нет опасных `DROP TABLE` и потери исторических данных.
4. Чувствительные legacy-заметки автоматически шифруются.
5. Нет Composer-зависимости от миграционного фреймворка.

## Последствия

### Положительные

- Рестарт контейнера не требует ручных действий.
- Новые nullable-колонки добавляются простым изменением массивов миграций.
- Единый процесс для dev и production.

### Отрицательные / риски

- Нет down-миграций и таблицы версий.
- `migrate.php` и обе схемы нужно обновлять согласованно.
- `ALTER TABLE` на больших MySQL-таблицах может блокировать запись.
- Разбиение MySQL-схемы по `;` ограничивает сложные процедуры.

## Альтернативы

| Альтернатива | Почему не выбрана |
|---|---|
| Phinx | Composer, CLI и конфиг ради 13 таблиц |
| Doctrine Migrations | Тянет DBAL/ORM и усложняет аудит |
| Ручные SQL-файлы | Легко забыть применить и нет идемпотентности |
| Пересоздание схемы | Потеря данных и downtime |
