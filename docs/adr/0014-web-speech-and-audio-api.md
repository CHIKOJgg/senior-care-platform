# ADR-0014. Web Speech API и Web Audio API для доступности

- **Статус:** Принято
- **Дата:** 2026-11-08
- **Категория:** Интеграция / браузер
- **Связанные ADR:** [ADR-0002](0002-vanilla-js-frontend-wcag.md), [ADR-0009](0009-emergency-112-adapter.md)

## Контекст

Пожилым пользователям сложно:

- набирать текст на маленькой клавиатуре (тремор, плохое зрение);
- читать мелкий текст и длинные инструкции;
- быстро найти кнопку SOS в стрессовой ситуации.

Нужны:

- голосовой ввод заявки и фразы для антифрод-проверки;
- озвучивание экрана, предупреждений и памяток;
- громкая сирена для координатора при входящем SOS;
- работа без установки приложений и без серверных затрат на STT/TTS;
- приватность: аудио не должно храниться на сервере.

## Решение

Используются **нативные браузерные API**:

### Web Speech API

`public/js/speech.js`:

- `window.SpeechRecognition || window.webkitSpeechRecognition` — распознавание речи (STT);
- `lang = 'ru-RU'`, `continuous = false`, `interimResults = false`;
- результат подставляется в поле заявки или антифрод-проверки;
- `SpeechSynthesis` — озвучивание (TTS) текста, предупреждений и памяток;
- голосовые команды экстренного вызова («Помощь», «SOS», «Тревога») распознаются в `checkEmergencyVoiceCommand()` и инициируют SOS;
- есть fallback: если API не поддерживается, выводится предупреждение и остаётся текстовый ввод.

### Web Audio API

В `public/js/app.js` (координатор):

- `AudioContext` / `webkitAudioContext`;
- `OscillatorNode` типа `sawtooth`;
- попеременные частоты **600 Гц** и **900 Гц** каждые **450 мс**;
- `GainNode` для плавного нарастания/затухания;
- кнопка отключения сирены;
- сирена запускается при активном SOS и останавливается после разрешения инцидента.

### Доступность

- кнопки с `aria-label`, крупные тач-таргеты (60px в senior-mode);
- `aria-live="assertive"` для SOS-баннера;
- текстовые дубли иконок;
- озвучивание по кнопке «Озвучить страницу».

## Обоснование

1. **Нет серверных затрат.** STT/TTS выполняются браузером; не нужны API-ключи, GPU и оплата за минуты.
2. **Приватность.** Аудио не отправляется на собственный сервер и не хранится; это снижает риск утечки ПДн.
3. **Доступность без установки.** Работает в браузере телефона/планшета, не требует отдельного приложения.
4. **Нативная поддержка русского.** `lang='ru-RU'` использует голоса ОС/браузера.
5. **Сирена без аудиофайлов.** Web Audio генерирует звук программно — нет зависимости от форматов и автозагрузки.
6. **Соответствие Zero-Emoji/WCAG.** Голос и звук дополняют визуальные подсказки, а не заменяют их.

## Последствия

### Положительные

- Пользователь может надиктовать заявку вместо набора текста.
- Слабовидящий может прослушать экран и предупреждения.
- Координатор замечает SOS по звуку даже при свернутом окне.
- Нет затрат на облачные STT/TTS.
- Нет хранения аудио на сервере.

### Отрицательные / риски

- **Поддержка браузеров неравномерна.** Web Speech Recognition лучше всего работает в Chrome/Edge; Firefox/Safari могут не поддерживать или требовать флагов. Нужен fallback (он есть: текстовый ввод).
- **Требуется HTTPS или localhost.** Микрофон и некоторые API доступны только в secure context; в production это обеспечивает Caddy.
- **Разрешение на микрофон.** Пользователь может отказать; нужен понятный сценарий и повторный запрос.
- **Облачная обработка у вендора.** В Chrome распознавание может идти через серверы Google; это не контролируется приложением и влияет на приватность.
- **Нет офлайн-гарантии.** Web Speech может не работать без сети; TTS зависит от установленных голосов.
- **Точность на пожилой речи.** Акцент, тихая речь, шум могут снижать качество; нужна возможность исправить текст.
- **Автовоспроизведение звука заблокировано.** Сирена может не запуститься без предварительного пользовательского жеста; нужен «разблокирующий» клик.
- **Web Audio требует `AudioContext`.** В некоторых браузерах нужен `resume()` после жеста.
- **Нет серверного логирования голосовых команд.** Для аудита SOS голосовая команда должна логироваться отдельно.

### Нейтральные

- Голосовые команды — дополнительный канал, а не единственный способ вызвать SOS.
- Сирена синтезируется, а не проигрывается из файла.

## Рассмотренные альтернативы

| Альтернатива | Почему отклонена |
|---|---|
| **Серверный Whisper/STT** | Нужны GPU/CPU, зависимость, стоимость, передача аудио и ПДн. |
| **Облачные TTS/STT (Google, Yandex, Azure)** | API-ключи, оплата, задержка, передача голоса за периметр. |
| **Записанные аудиофайлы** | Нужны хостинг, форматы, автозагрузка; сирена проще синтезируется. |
| **Отдельное мобильное приложение** | Высокий порог для пожилых, установка, обновления. |
| **Только текстовый ввод** | Не решает проблему тремора/зрения; хуже доступность. |
| **Аппаратная кнопка SOS** | Требует устройства и интеграции; вне scope веб-платформы. |
