# ADR-0002. Vanilla JS и CSS без сборки, приоритет WCAG 2.1 AAA

- **Статус:** Принято
- **Дата:** 2026-11-22
- **Категория:** Frontend
- **Связанные ADR:** [ADR-0001](0001-php82-custom-mvc.md), [ADR-0014](0014-web-speech-and-audio-api.md)

## Контекст

Основная аудитория — пожилые люди, в том числе со слабым зрением, тремором рук и недорогими устройствами. Интерфейс должен иметь крупные элементы, высокий контраст, понятную навигацию и голосовое сопровождение. Дополнительно нужны кабинеты волонтёра и координатора с таблицами, фильтрами и динамическими панелями.

## Решение

Фронтенд реализован на чистом HTML5, CSS3 и JavaScript ES6+:

```text
public/index.php            серверный HTML-каркас и role-based секции
public/css/accessibility.css дизайн-система, senior-mode, focus-visible
public/js/app.js            API-клиент, рендеринг, поллинг, модальные окна
public/js/speech.js         Web Speech API и голосовые команды
public/verify.php           публичная проверка бейджа
```

Принципы:

- CSS-переменные и отдельный режим крупного шрифта.
- Тач-таргеты не меньше 60px в senior-mode.
- Видимый `:focus-visible` и навигация с клавиатуры.
- Inline SVG вместо эмодзи во всех интерфейсах.
- `aria-live`, `aria-label` и текстовые дубли иконок.
- Автоопределение `prefers-contrast`, `forced-colors`, `prefers-reduced-motion` и тёмной темы.

## Обоснование

1. Предсказуемый DOM проще проверять на соответствие WCAG.
2. Нет Node.js, bundler и source maps в production.
3. Страница быстро становится интерактивной на слабом устройстве.
4. Один и тот же код работает локально и в Docker.
5. Нативные Web Speech API и Web Audio API не требуют обёрток.

## Последствия

### Положительные

- Малый вес страницы и полный контроль над семантикой.
- Легко тестировать ARIA, размеры таргетов и zero-emoji политику.
- Нет зависимости от breaking changes UI-фреймворка.

### Отрицательные / риски

- Императивное управление DOM и риск рассинхронизации состояния.
- Нет реактивности, компонентной модели и типизации.
- Данные, вставляемые через шаблонные строки, требуют дисциплины экранирования.
- Поллинг создаёт постоянный фоновой трафик.

## Альтернативы

| Альтернатива | Почему не выбрана |
|---|---|
| React | Сборка, гидратация и риск ухудшить доступность |
| Vue | Node.js и toolchain без решающего выигрыша |
| Svelte | Компилятор и сборка противоречат выбранному no-build подходу |
| jQuery | Лишний вес и устаревшая модель работы с DOM |
| TypeScript | Требует транспиляции и отдельного build-этапа |
