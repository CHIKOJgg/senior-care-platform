# Комплексная методология тестирования, регрессионный контроль и аудит безопасности
## Стратегия обеспечения качества и валидации платформы «ЗаботаРядом»

### 1. Архитектура 5-уровневого комплекса тестирования
Для гарантии абсолютной надёжности при эксплуатации в реальных условиях (взаимодействие с экстренными службами МЧС, пожилыми людьми и персональными данными граждан) платформа покрыта пятиуровневым набором автоматизированных тестов:

```
                      / \
                     /   \
                    / T5  \  White-Box Adversarial Hardening (Стресс-тесты, криптоатаки)
                   /-------\
                  /   T4    \  Real-World Scenarios (10 сквозных жизненных сценариев)
                 /-----------\
                /     T3      \  Cross-Feature Interactions (Межкомпонентные цепочки)
               /---------------\
              /       T2        \  Boundary & Corner Cases (Экстремальные координаты, лимиты)
             /-------------------\
            /         T1          \  Feature Coverage (24 фичи x 5 тестов = 120 тестов)
           /-----------------------\
```

#### 1.1. Tier 1: Feature Coverage (Покрытие функциональных контрактов)
- Файл: `tests/e2e_suite/Tier1_FeatureCoverageTest.php`.
- Объем: 24 системные фичи $\times$ 5 детерминированных тестов = 120 тестов.
- Предмет проверки: корректность базовых контрактов API, структура базы данных SQLite, криптографические операции AES-256-GCM, маскирование телефонов и адресов по Закону № 99-З, валидация адаптеров МСИ/Госуслуг, вычисление Haversine и доступность шаблонов.

#### 1.2. Tier 2: Boundary & Corner Cases (Граничные и экстремальные случаи)
- Файл: `tests/e2e_suite/Tier2_BoundaryCornerTest.php`.
- Объем: 65+ тестов.
- Предмет проверки:
  - Границы геозоны Haversine ($0.0$ м, $149.9$ м, $150.0$ м, $150.1$ м, антиподы $[0,0] \leftrightarrow [0,180]$ с проверкой численного клемпинга).
  - Крайние значения координат ($\pm 90^\circ, \pm 180^\circ$).
  - Вариации типографских кавычек, пробелов и буквы «ё» в секретных кодовых словах.
  - Порог блокировки перебора кода (блокировка на 5-й попытке).
  - Срабатывание ограничений частоты запросов (`RateLimiter`).

#### 1.3. Tier 3: Cross-Feature Interactions (Сквозные межкомпонентные взаимодействия)
- Файл: `tests/e2e_suite/Tier3_CrossFeatureTest.php`.
- Объем: 35+ комплексных тестов.
- Предмет проверки:
  - Создание заявки $\to$ маскирование $\to$ принятие верифицированным волонтёром $\to$ демаскирование $\to$ закрытие визита по GPS $\to$ начисление кармы $\to$ генерация цифрового QR-бейджа.
  - Отзыв аккредитации координатором $\to$ немедленная инвалидация активного бейджа и блокировка принятия задач.
  - Запрос на забвение $\to$ блокировка при незавершённых заявках $\to$ исполнение после закрытия.

#### 1.4. Tier 4: Real-World Scenarios (Сценарии реальной эксплуатации)
- Файл: `tests/e2e_suite/Tier4_RealWorldScenariosTest.php`.
- Объем: 10 детальных пользовательских историй (50 шагов):
  1. Доставка продуктов пожилому человеку в Советском районе.
  2. Срочная доставка лекарств со срабатыванием сторожевого таймера (Watchdog 60 мин) и переназначением координатором.
  3. Экстренный вызов SOS подопечным с эмуляцией оповещения МЧС (112) и светозвуковой сиреной на пульте.
  4. Регистрация нового волонтёра, валидация личного номера МСИ, модерация ТЦСОН и сканирование бейджа.
  5. Полный жизненный цикл реализации права на забвение (Закон № 99-З).
  6. Обнаружение попытки финансового мошенничества антифрод-сканером.
  7. Массовая координация районных заявок без состояния гонки (Race Condition).
  8. Защита от перехвата чужих заявок и брутфорса кодового слова.
  9. Очная проверка геозоны присутствия ($>150$ м отклонено, $\le 150$ м принято).
  10. Координация в чате задачи и выставление оценки качества.

#### 1.5. Tier 5: White-Box Adversarial Hardening (Белоящичные тесты на взлом и аудит)
- Набор специализированных испытаний:
  - `tests/test_adversarial_m3_geofence.php`: математические атаки на алгоритм Haversine, попытки подделки координат.
  - `tests/test_adversarial_badge_qr.php`: попытки фальсификации HMAC-подписи бейджа, повреждение бит в QR-коде с проверкой коррекции ошибок Рида-Соломона.
  - `tests/test_adversarial_m2.php`: проверка граничных номеров СНИЛС по модулю 101 и фальшивых паспортов МСИ.
  - `tests/test_adversarial_m3_sos.php`: стресс-тестирование очереди SOS при отключении шлюза МЧС.
  - `tests/adversarial_privacy_test.php`: попытки подделки тега аутентификации AES-256-GCM и инъекций в базу данных.

### 2. Регрессионный запуск и критерии приёмки
Главная точка входа в систему приёмочного тестирования:
```bash
docker exec senior_care_platform php tests/e2e_suite/run_e2e.php --strict --json
```

Критерии прохождения приёмочной верификации:
1. **0 Failures**: 100% тестов должны иметь статус `PASS`.
2. **0 Skips**: в режиме `--strict` ни один тест не должен быть пропущен.
3. **Целостность базы данных**: отсутствие повреждений внешних ключей и уникальных ограничений.
4. **Формирование отчёта**: генерация машиночитаемого отчёта `tests/e2e_report.json`.

### 3. Критерии судебно-криминалистического аудита (Forensic Audit)
Независимый аудит проверяет подлинность всех реализаций платформы:
- **Zero-Emoji Compliance**: полное отсутствие Unicode-эмодзи во всех файлах разметки (`.php`, `.html`, `.css`, `.js`).
- **WCAG 2.1 AAA Accessibility**: сохранение контрастности не менее 21:1 в senior-mode, размер активных зон $\ge 60$px, видимый фокус клавиатуры 3px.
- **Подлинность алгоритмов**: отсутствие захардкоженных тестовых результатов, генерация реальных математических значений Haversine и реальное состояние в SQLite.
