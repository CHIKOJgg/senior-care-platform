# Архитектурный обзор платформы «ЗаботаРядом»
## Комплексная архитектура системы взаимопомощи (Советский район г. Минска)

### 1. Миссия и цели системы
Платформа «ЗаботаРядом» спроектирована как социально защищённая цифровая экосистема взаимной помощи для одиноких пожилых граждан, маломобильных людей, верифицированных волонтёров и специалистов Территориального центра социального обслуживания населения (ТЦСОН) Советского района г. Минска.

Ключевые приоритеты платформы:
- **Безопасность подопечных**: многоуровневая верификация волонтёров, геозонирование присутствия (Proof-of-Presence) по формуле Haversine, динамические QR-бейджи и приоритетный протокол экстренного реагирования SOS с эмуляцией передачи данных в дежурную службу МЧС 112.
- **Соответствие законодательству Республики Беларусь**: строгое соблюдение Закона Республики Беларусь от 7 мая 2021 г. № 99-З «О защите персональных данных», регламентов регуляторов (НЦЗПД) и стандартов доступности для лиц с ограниченными возможностями (WCAG 2.1 AAA / СТБ).
- **Отказоустойчивость и автономность**: чистое PSR-4 модульное MVC-ядро на PHP 8.2 без внешних Composer-зависимостей, легковесная реляционная СУБД SQLite 3 в режиме WAL, SPA-клиент на Vanilla JavaScript с полной поддержкой офлайн-устойчивости.

### 2. Архитектурная топология
Платформа организована по классической многоуровневой сервисно-ориентированной архитектуре (Tiered Architecture):

```
+-----------------------------------------------------------------------------------+
|                        УРОВЕНЬ ПРЕДСТАВЛЕНИЯ (CLIENT SPA)                         |
|  Vanilla JS (ES6+), Accessible CSS (WCAG 2.1 AAA, 21:1), Web Speech & Audio API  |
|  Маршруты: / (Главный интерфейс), /verify.php (Публичная верификация бейджей)     |
+-----------------------------------------------------------------------------------+
                                          |
                                          | HTTP / JSON REST API (Bearer Auth)
                                          v
+-----------------------------------------------------------------------------------+
|                     УРОВЕНЬ ПРИЛОЖЕНИЙ И БИЗНЕС-ЛОГИКИ (MVC)                      |
|  app/Core/: Router, Database (PDO), Model, Controller, RateLimiter, Logger        |
|  app/Controllers/: Auth, HelpRequest, Volunteer, Elderly, Coordinator, Sos...     |
|  app/Services/: CryptoService (AES-256-GCM), DataMaskingService, PrivacyService,  |
|                 GeoMatchingService, BadgeService, TaskWatchdogService             |
|  Адаптеры: Identity/ (MSI Belarus, Gosuslugi Mock), Emergency/ (EMERCOM 112)      |
+-----------------------------------------------------------------------------------+
                                          |
                                          | PDO SQLite Connection (PRAGMA foreign_keys = ON)
                                          v
+-----------------------------------------------------------------------------------+
|                           УРОВЕНЬ ХРАНЕНИЯ ДАННЫХ (PERSISTENCE)                   |
|  SQLite 3 (database/database.sqlite): 12 таблиц, 11 индексов, миграции migrate.php|
+-----------------------------------------------------------------------------------+
```

#### 2.1. Уровень представления (Presentation Tier)
- **Одностраничное веб-приложение (Single Page Application)**: реализовано на чистом Vanilla JavaScript (`public/js/app.js`, `public/js/speech.js`) без фреймворковых зависимостей.
- **Дизайн-система доступности**: `public/css/accessibility.css` обеспечивает коэффициент контрастности не менее 21:1 (7:1 для вспомогательных элементов), увеличенные интерактивные зоны от 60px, видимый контур фокуса клавиатуры `:focus-visible` толщиной 3–4px.
- **Политика Zero-Emoji**: полное отсутствие Unicode-эмодзи в разметке и скриптах; все пиктограммы выполнены в виде 100% векторных масштабируемых SVG-элементов.
- **Аудио- и голосовой интерфейс**: интеграция Web Speech API для голосового ввода заявок и озвучивания сообщений слабовидящим подопечным, а также Web Audio API для аппаратного синтеза тревожной сирены координатора.

#### 2.2. Уровень приложений и API (Application Tier)
- **MVC-архитектура**: строгое разделение ответственности по стандарту PSR-4.
- **Фронт-контроллеры**:
  - `public/index.php`: обслуживает пользовательский интерфейс платформы.
  - `public/api.php`: обслуживает маршрутизацию 35+ REST API эндпоинтов.
  - `public/verify.php`: изолированная публичная страница проверки QR-бейджей волонтёров.
- **Безопасность и криптография**: встроенные сервисы шифрования чувствительных данных (AES-256-GCM), маскирования контактов по Закону № 99-З, вычисления расстояния Haversine и цифровой подписи бейджей (HMAC-SHA256).

#### 2.3. Уровень хранения данных (Persistence Tier)
- СУБД SQLite 3 с принудительной активацией ограничений внешних ключей (`PRAGMA foreign_keys = ON;`).
- Набор из 11 индексов для ускорения аналитических выборок, поиска просроченных задач и валидации токенов за $O(1)$.
- Идемпотентный механизм миграций (`database/migrate.php`) с интроспекцией схемы через `PRAGMA table_info`.

### 3. Модель акторов и ролевая модель доступа (RBAC)
В системе определены 5 ключевых акторов:

1. **Подопечный (Elderly Citizen, роль `elderly`)**:
   - Одинокие пожилые люди и маломобильные граждане.
   - Возможности: создание голосовых и текстовых заявок, получение проверочного секретного слова, вызов экстренной помощи SOS (Приоритет 0), управление электронными согласиями и реализация «права на забвение».
2. **Волонтёр (Volunteer, роль `volunteer`)**:
   - Добровольцы, прошедшие проверку личности.
   - Возможности: выбор заявок в районе проживания, предъявление динамического бейджа с QR-кодом, завершение заявок с передачей GPS-координат и проверкой секретного слова, отслеживание личного рейтинга и знаков отличия.
3. **Координатор ТЦСОН (Coordinator, роль `coordinator`)**:
   - Штатные сотрудники районного центра соцобслуживания.
   - Возможности: модерация анкет волонтёров (проверка паспорта и справок об отсутствии судимости), оперативный контроль экстренных вызовов SOS со светозвуковой консолью, мониторинг зависших задач через Task Watchdog, переназначение заявок в 1 клик, публикация предупреждений о мошенниках.
4. **Администратор системы (Administrator, роль `admin`)**:
   - Технический персонал платформы.
   - Возможности: конфигурация системных параметров, аудит журналов безопасности, управление учетными записями всех ролей, запуск регламентных процедур.
5. **Дежурная служба МЧС 112 (Emergency Services Adapter)**:
   - Внешний шлюз экстренного реагирования.
   - Обеспечивает автоматический приём сигналов SOS, генерацию официальных квитанций (`EMERCOM-112-BY-2026-XXXX`) и назначение спасательных расчётов (ПАСЧ-24 Советского РОЧС г. Минска).

### 4. Жизненный цикл заявки и информационные потоки
1. **Создание заявки**:
   - Подопечный диктует или заполняет заявку в форме `#helpForm`.
   - Система фиксирует электронное согласие в таблице `user_consents` per Закон № 99-З.
   - Сервер присваивает заявке случайное доброжелательное секретное слово из природного словаря («Василёк», «Ромашка» и др.).
2. **Публикация в ленте с маскированием ПД**:
   - Номер телефона маскируется: `+375 (29) ***-**-67`.
   - Номер квартиры заменяется: `кв. ***` (улица и дом остаются открытыми для оценки логистики).
3. **Принятие заявки верифицированным волонтёром**:
   - Волонтёр со статусом `VERIFIED` принимает задачу (`POST /api/requests/{id}/accept`).
   - Статус переходит в `in_progress`. Волонтёру открываются демаскированные контакты и запускается тайм-аут сторожевого таймера (Watchdog).
4. **Очный визит и проверка аккредитации**:
   - Волонтёр предъявляет динамический бейдж с QR-кодом (`#volunteer-badge-modal`).
   - Подопечный или родственники сканируют QR и на странице `public/verify.php` видят официальное подтверждение ТЦСОН без избыточных ПД волонтёра.
5. **Подтверждение присутствия (Proof-of-Presence) и закрытие**:
   - Подопечный называет волонтёру секретное слово.
   - Волонтёр открывает форму закрытия визита, браузер опрашивает `navigator.geolocation`.
   - Сервер проверяет совпадение слова и рассчитывает расстояние по формуле Haversine ($d \le 150.0$ м).
   - Заявка переходит в статус `completed`, волонтёру начисляется +50 очков опыта, статистика сохраняется в реестре.
